# 任务：上游跟进策略与方向决策（落档）

## 背景

20261120 方向复盘：对独立输入栏的可行性产生疑虑（「都是胶水」疲劳感），提出新思路「架子（脚手架）+ alacritty：架子只管单 alacritty 进程的 tab/pane/广播，撇弃独立输入栏」。经架构体检后否决该提案，同步确立上游（raphamorim/rio）更新的跟进机制，本文档为该决策的归档。

## 方向决策（拍板结论）

1. **保留现架构**（自研栈 tap-vt / teletypewriter / sugarloaf / tap-window / corcovado + 输入栏产品层），不换引擎。理由：
   - 胶水仅在补全适配层（completion.rs），可选、有界（`dynamic-completion = false` 即回退）；引擎层是 700+ 测试的自研资产
   - 提案动的是引擎层，痛点在产品层——换引擎不减少任何胶水；且 tab/pane/广播在 todolist 中均已交付，「架子」等于重建已建成之物
   - 字面义「嵌入真 alacritty 进程」平台不可行：Wayland 无跨窗口嵌入协议、macOS 无公开嵌入 API、alacritty 不实现 XEmbed；库替换（alacritty_terminal）则丢 sixel/kitty 图像、sugarloaf 集成与测试资产，引入 0.x API churn
   - 输入栏硬骨头（ALT_SCREEN 锁定、termios 密文、IME preedit、ssh 探测、Cobra 协议、ControlMaster 侧信道）均已真实 GUI 闭环验证，「无法实现」不成立，剩余为已声明边界
2. **补全范围冻结**：四类补全（静态命令/路径、Cobra `__complete` 动态、ssh 一次性、ssh 会话侧信道）即终点，bug 驱动修复，不再新增适配器类。
3. 开发节奏：**用起来，慢慢修**——issue/实测反馈驱动，不做范围主动扩张。

## 上游（raphamorim/rio）跟进策略

上游仍有价值：终端模拟 / PTY 平台适配 / 字体渲染是单人维护最易翻车的域，上游曝光量大、bug 先暴露先修复。改名（20261119-2244，399 路径全量 rio→tap）后 git merge 上游全量冲突不可用，故采用 **port 模式**。

### 价值梯度

| 梯度 | 上游改动域 | 处置 |
|---|---|---|
| 高价值，按 release 评估移植 | tap-vt 终端模拟修复（ANSI 边角/grid/宽字符）、teletypewriter 平台适配（新 macOS/Windows ConPTY/Wayland）、tap-window IME/输入修复、sugarloaf 字体/渲染修复、安全修复 | cherry-pick / 手工移植，套改名映射 |
| 中价值，按需 | 性能优化、图像协议演进（kitty graphics 等） | 与本项目特效需求相关才跟 |
| 低价值，跳过 | 上游产品功能、打包、品牌物料 | 不跟 |

### 机制

- release 粒度评估，不逐 commit；`git fetch upstream --tags` 后对照 CHANGELOG 圈定候选
- 移植时套用改名映射（rio→tap，保护词清单见 20261119-2244 任务：period/prior/ity/criterion/interior/scenario/various/spurious/serious/Canario）
- **判停条件**：上游大重构（换引擎/架构翻新）致移植成本超过照 diff 自修，即停止跟进，此后按 bug 自修
