# ssh 会话内远程路径补全

## 背景

用户报告：ssh 到目标机器后输入 `cd` 再 Tab，路径补全无效果。

根因：ssh 会话内的路由（completion.rs `route` 会话分支）只覆盖两类词——首词查远程命令名（compgen）、Cobra 工具查远程 `__complete`；非 Cobra 命令的后续词一律 `Route::None`（当时注释即 "no remote path completion"）。`cd <Tab>` 正落在空洞里。

## 设计

新增 `DynamicRequest::RemotePaths { host, word }` 动态请求，复用既有 ssh 侧信道（BatchMode + ControlMaster 复用，提交 ssh 行时已预热，首 Tab 毫秒级），远程执行 `compgen -A file` 脚本。

**cwd 不可见是核心约束**：侧信道每次是 sshd 新 spawn 的 bash，cwd 恒为远程 home；交互 shell 的真实 cwd 对它不可见（远程 shell 默认不发 OSC 7，pane 的 OSC 7 cwd 在 ssh 会话内会回落到本地探测值，不可信）。因此锚定策略按词自带的信息分层：

- 裸词（`cd <Tab>`、`cd Doc<Tab>`）：在远程 home 下匹配——覆盖 ssh 登录后直接操作的主场景
- 带目录头的词（`src/`、`./`、`/var/log/x`）：compgen 自行走该头，精确
- `~` 词：远程侧先按 `$HOME` 展开（`${1/#~/$HOME}`）再匹配，结果行把 `$HOME` 前缀映射回 `~`，保持 `~/` 简写且 `sh_escape` 对 `~/` 前缀不加转义（可继续 tilde 展开）

脚本其余语义对齐本地静态路径补全：隐藏项仅在词以 `.` 开头时出现、目录带尾 `/`、过滤 `./` `../`、`head -n 100` 截线（MAX_CANDIDATES）。

结果后处理：脚本以尾 `/` 标记目录，worker 侧 `mark_trailing_slash_dirs` 镜像到 `is_dir`——唯一目录候选不加尾空格，下一 Tab 继续下降。

**实现坑（本地 bash 实测抓出）**：参数展开替换文本里的裸 `~` 会被 tilde 展开（`${f/#$h/~}` 得到 `/home/user/...` 而非字面 `~`），必须写 `\~`。

路由填洞：

- 会话内首词：路径形态（含 `/`、`~`、`.` 开头，新 `is_path_word`）→ RemotePaths；否则 RemoteCommands（远程命令名，原行为）
- 会话内后续词：Cobra 工具 → Cobra；其余一律 RemotePaths（原 `Route::None`）
- one-shot `ssh host cmd …` 行：远程非 Cobra 词同样 RemotePaths（原 `Route::None`）
- `Route::None` 仅剩 one-shot 的 flags 区间

明确边界：远程脚本假设 bash 存在（与 RemoteCommands 的 compgen 同假设）；`~user/` 形式不支持；文件名以 `:` 开头会被 `parse_complete_output` 的 directive 行误吞（Cobra 解析共用的既有边界，不扩散处理）。

## 修复轮次一（20261120-1801）：目录专属命令只补目录

用户反馈：ssh 下 `cd <Tab>` 把目录和文件一股脑列出——补全缺少命令上下文语义（bash/zsh 的 `cd` 只补目录；本地静态补全同样存在此问题）。

修复：目录专属命令表 `cd`/`pushd`/`rmdir`（completion.rs `DIR_ONLY_COMMANDS`），`is_dirs_only_context(argv)` 取光标前最后一个非 flag 词判定（`cd -P <Tab>` 命中、`cd a b<Tab>` 不命中）。两处生效：

- 本地静态：`filter_dirs_only` 在 input_bar 两个静态分支（Path/Command 与 dynamic 关闭时的 legacy 分支）对 `path_candidates` 结果过滤，仅保留 `is_dir`。
- 远程：`RemotePaths` 加 `dirs_only` 字段（route 会话/one-shot 分支判定，进 `key()` 缓存槽），脚本 `compgen -A {file|directory}` 切换——实测 `-A directory` 的裸词/前缀/目录头下降均正常（排查中两轮「空输出」实为测试词大小写与拼写错误，`compgen` 本身大小写敏感，与远端 readline 语义一致）。

测试 +5：route 的 cd 上下文断言（会话内 `cd <Tab>` → dirs_only）、`is_dirs_only_context` 六例、`filter_dirs_only` 过滤、脚本 `-A directory` 切换断言、input_bar 端到端（`cd d<Tab>` 落目录、`ls d<Tab>` 双候选不变）。tapterm 386（+5）通过。

## 修复轮次二（20261120-1815）：远程补全大小写折叠

用户反馈：本地补全已折叠大小写，远程仍是精确匹配——不一致。

修复：bash `shopt -s nocasematch`（3.1+，更老 bash 静默退回精确匹配不回归）在脚本循环内折叠匹配。compgen 本身是精确前缀过滤（`d` 在源头滤掉 `Docs`，折叠无处可施），故改为：compgen 只接收**目录头**（精确，`w` 无 `/` 时传空 = 列全量），尾组件在 while 循环里以 `case ${f##*/} in "$t"*)` 折叠比对（quoted 字面安全，`[` 等特殊字符不误当 glob），过滤后再 `head` 截断（顺序不能反，否则截掉真匹配）。顺带修正：隐藏项门控从整词 `case $w` 改为尾组件 `case $t`——原实现 `Doc/.x` 形态（目录头 + 点尾词）会被误过滤隐藏项。

目录头精确、仅尾组件折叠，与远端 readline 行为分层一致。

脚本实测五场景：`d` 折叠出 `Dot.txt`+`Docs/`；`Docs/i` 折叠出 `Inner.txt`；`Docs/.` 只出隐藏；`~/Docs/i` 保 `~` 头；不存在的头（`DOC/`）无候选。
