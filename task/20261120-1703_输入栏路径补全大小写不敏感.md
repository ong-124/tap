# 输入栏文件路径补全大小写不敏感

## 背景

用户报告：输入栏 Tab 补全中文件路径匹配区分大小写，输入 `foo` 无法补到 `Foo.txt`，不够智能，要求改为不分大小写。

## 设计

匹配折叠大小写、排序保留智能，三处配合：

1. **候选匹配**（completion.rs `path_candidates`）：组件名前缀比较从 `starts_with` 改为大小写折叠的 `starts_with_ignore_case`（ASCII 折叠，非 ASCII 逐字比较——CJK 无大小写，完整 Unicode folding 不值目录扫描的开销）。排序改为双级：精确大小写命中排前（输入 `f` 时 `foobar` 先于 `Foo.txt`），组内按 insert 字典序；隐藏项点号门控不变。
2. **候选守卫**（input_bar.rs `apply_candidates_at`）：「候选须为当前词超集否则整组丢弃」的防缩短校验同步折叠大小写。多候选分支不能拿 LCP 顶替——混合大小写候选共享的精确前缀可能为空（`Foo.txt` vs `foobar`），但每个候选仍延伸输入词，故改为逐候选比较。
3. **空 LCP 循环状态**（input_bar.rs `apply_candidates_at`）：LCP 为空时不插入任何文本，`CompletionState.current` 原存 `prefix_word`（空串）导致下一 Tab 判定 stale、菜单永远无法进入循环。改为：插入了 LCP 存 `prefix_word`，未插入存已输入词本身。

明确不动：命令补全（PATH 可执行 + 内建）与 ssh 主机表维持大小写敏感（二进制名与主机名均为大小写敏感标识符，用户仅报告路径）；Cobra 动态补全由工具自身语义决定。

## 实施记录

- frontends/tapterm/src/completion.rs：
  - 新增 pub `starts_with_ignore_case(name, prefix)`（ASCII 折叠前缀比较，input_bar 共用）。
  - `path_candidates`：匹配改用 `starts_with_ignore_case`；排序改双级键（`display.starts_with(prefix)` 精确命中优先，再按 insert 排序）；doc comment 补充匹配语义。
  - 测试 +1：`path_completion_matches_case_insensitively`（任意大小写命中真名、精确命中优先、非 ASCII 逐字）。
- frontends/tapterm/src/renderer/input_bar.rs：
  - `apply_candidates_at` 单候选守卫改 `starts_with_ignore_case`；多候选守卫改逐候选 `extends_word` 闭包；`current` 按「是否插入了 LCP」取 `prefix_word` 或已输入词。
  - 测试 +2：`tab_path_completion_ignores_case`（大写查询插入真名 + 尾空格）、`tab_mixed_case_candidates_open_menu_without_shortening`（空 LCP 只开菜单不缩短输入，下一 Tab 落精确命中候选）。
  - 顺手修复既有 clippy `manual_slice_fill` 警告（密文掩码循环改 `chars.fill(MASK_CHAR)`，20261120-1606 遗留清单项之一）。
