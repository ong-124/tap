# 任务：全项目 rio → tap 改名

## 背景与目标

项目 fork 自 rio（终端模拟器），此前已完成二进制与配置目录改名（`tap`、`~/.config/tap`），但代码库中仍大量残留 rio：crate 目录名（rio-vt、rio-backend、rio-window、librio…）、包名、标识符（`rio_config`、`RioEvent`、`RIO_KEY_*`）、shell 集成脚本、man 手册、打包脚本（pkgRio.nix、wxs、metainfo）、CI workflow、文档与 URL。目标：不留 rio 痕迹，全部改为 tap。

## 设计

- 映射规则（机械替换，保持大小写）：`rio→tap`、`Rio→Tap`、`RIO→TAP`；由此 rio-vt→tap-vt、librio→libtap、rioterm→tapterm、frontends/rioterm→frontends/tapterm、`rio_key_event_s→tap_key_event_s`、`RIO_LOG_LEVEL→TAP_LOG_LEVEL`、xterm-rio→xterm-tap、com.rioterm.Rio→com.tapterm.Tap 一并成立；二进制名保持 `tap`（20261118-2110 已改，无 rio 字样不受影响）
- 误伤保护：period / prior(ity) / criterion / interior / scenario / various / spurious / serious / PERIOD（VK_OEM_PERIOD）/ PRIOR（VK_PRIOR）/ Canario（CPU 渲染器专名）先以哨兵置换、再做 rio→tap 替换、最后还原（首轮 `@@T6@@` 哨兵被 perl 数组插值塌缩成 `@@@` 致保护词全变 period，`git restore --worktree .` 回滚后改用字母哨兵 ZQPROTnQZ 重跑成功）
- logo 例外：misc/logo.svg、misc/logo-2024.svg 中残留的 4 处 rio 字节序列位于 base64 像素数据内，不动（动了会损坏图片）；图标/壁纸图片内容本身仍是原 logo 画作，如需换标另行处理

## 关键子任务

1. git mv 目录改名（rio-* ×8、librio ×2、frontends/rioterm、misc/osx/Rio.app）
2. 散落文件改名（pkgRio.nix、extra/man/rio*.scd、misc/rio.terminfo/termcap/metainfo/windows、.github/workflows/librio.yml、specs/librio.md、rio-logo.ico、shell_integration/rio-* 等，合计 399 个路径）
3. 全库文本内容替换（git 跟踪的文本文件，含 Cargo.lock、CHANGELOG、task/ 历史文档）
4. 验证：残留扫描、保护词抽查、cargo check --workspace --all-targets

## 实施记录

- git mv：12 个目录 + 文件名循环改名（sed 三种大小写逐字符替换路径），`git ls-files | grep -i rio` 为空，无 rio 路径残留
- 内容替换：`git grep -IlzE 'rio|Rio|RIO'`（排除 logo SVG）→ perl 哨兵保护替换；中文路径文件首轮因 git quotepath 八进制转义漏跑，`core.quotepath=false` + NUL 分隔重跑覆盖（脚本幂等）
- 验证：全库仅剩 misc/logo.svg 4 行 base64 内 rio 序列与保护词本身；criterion（Cargo.toml:80）、VK_PRIOR / VK_OEM_PERIOD（tap-window）、Canario（libsugarloaf）、video_refresh_period / send_event_with_high_priority 等抽查完好；cargo metadata 与 cargo check --workspace --all-targets 通过（teletypewriter 1 个既有测试警告，该文件本次零改动）
- 已知边界：上游 URL（github.com/raphamorim/tap、tapterm.com 等）为机械替换后的死链；sugarloaf / corcovado / teletypewriter / Canario 等里约主题命名不含 rio 字样，未在本次范围
