# 任务：Warp 式底部统一输入框

## 背景与目标

像 Warp 终端一样，在终端窗口底部提供一个统一的输入框：所有键盘输入先进入底部输入栏，支持行内编辑与历史记录，回车后将整行命令发送到 PTY，输出区（上方终端面板）只读展示。

## 需求细节

- 底部固定输入栏，光标常驻输入栏
- 行内编辑：左右移动、Home/End、退格、删除、Ctrl+W 等
- 历史记录：上/下翻阅已执行命令
- 回车提交：整行（含换行）写入 PTY；清空输入栏
- 可配置启用/禁用：关闭后回到传统"直接输入到终端"模式

## 设计调研（20261118 架构调研结论）

- 参考现有覆盖层 UI：`frontends/tapterm/src/renderer/command_palette.rs`（命令面板）、`island.rs`、`search.rs`、`assistant.rs`
- 渲染 API：`sugarloaf/src/sugarloaf.rs`（`rect` L566、render 系列 L909-1133）；富文本布局 `sugarloaf/src/layout/mod.rs`（`RichTextConfig` L146）、`sugarloaf/src/span.rs`、UI 文本 `sugarloaf/src/text.rs`
- 键盘事件链路：`frontends/tapterm/src/application.rs` L2215 `WindowEvent::KeyboardInput` → `frontends/tapterm/src/router/mod.rs` `has_key_wait` L268（overlay 优先接管输入）→ `frontends/tapterm/src/screen/mod.rs::process_key_event` L802
- 输出到 PTY：`frontends/tapterm/src/messenger.rs::send_write`（corcovado channel）
- 终端区滚动/布局：输入栏占位需要与终端内容区布局协调（避免遮挡最后一行）

## 关键子任务

1. 输入栏 UI 与渲染层（底部固定栏，sugarloaf 富文本）
2. 输入缓冲与编辑（光标移动、历史记录）
3. 提交发送整行命令到 PTY
4. 可配置启用/禁用（保留传统直接输入模式）

## 设计方案（20261118 获批实施计划，行号为计划时点）

**用户确认的决策**：① 智能路由跟随焦点 pane 状态（OSC 133 + alt-screen 兜底），无任何 133 标记时降级为输入栏常激活；② 控制组合键（Ctrl+C/D/Z/L…）直通 PTY（Ctrl+C 直通同时清空输入栏缓冲）；③ 配置 `enable-input-bar` 默认 true；④ 粘贴（Ctrl+V/中键/IME commit 多字符）进输入栏缓冲；⑤ 历史仅内存态（容量 255，相邻去重），Tab/Escape/Ctrl+D 等一律直通（已知限制）。

### 总体数据流

```
按键 → process_key_event（screen/mod.rs:809）
  preedit保护 → Released(kitty) → hint → key bindings（app快捷键优先）
  → search分流 → VI → ★输入栏分支（新，插在 L921 后）
      enabled 且未锁定：编辑键/可打印文本→buffer；Ctrl+W/U→编辑；
        Ctrl+C→清buffer后直通；Enter→整行+\r→send_write
      锁定（!at_prompt 或 ALT_SCREEN）→ 返回false走原编码路径直通PTY

PTY reader线程 OSC 133: A/N→prompt_start→input_zone=Prompt
                         C→command_start→input_zone=Running
  zone翻转→request_render()（crosswords/mod.rs:757 既有机制）→ 触发重绘更新锁定视觉

布局: margin.bottom += INPUT_BAR_HEIGHT(36) → layout compute 行数减少 → PTY winsize 自动同步
渲染: renderer.run overlay 区无条件绘制底栏（rect+文字+闪烁caret+preedit ghost）
帧驱动: input_bar.next_wake_in() → schedule_render_on_route（scrollbar 同模式）
```

## 实施记录

### 设计决策（20261118-2257 实施前确认）

- **智能路由（核心）**：输入栏只负责命令输入，编辑由用户在目标 pane 自行完成。基于 OSC 133 shell integration 跟踪焦点 pane 状态：提示符 → 按键进输入栏；命令运行中 → 输入栏锁定（变暗+提示文案），按键直通 PTY，退出程序回提示符自动恢复。锁定判定附加 **alt-screen 兜底**（`!at_prompt() || ALT_SCREEN`），bash（无 133）下 vim/less/tmux 仍可正确锁定；从未收到任何标记时降级为输入栏常激活
- **控制组合键直通 PTY**：Ctrl+C/D/Z/L 等原样发送控制字节；Ctrl+C 直通同时清空输入栏缓冲（避免 shell 重绘空 prompt 后残留旧文本）
- **配置默认开启**：`enable-input-bar = true`
- **粘贴进输入栏缓冲**：Ctrl+V/中键/IME commit 多字符统一经 `screen.paste` 分流进缓冲
- **历史仅内存态**：容量 255、相邻去重、编辑历史项即分叉（readline 语义）；Tab 补全/Ctrl+R 等 shell 自身行编辑交互不可用（已知限制）

### 修复轮次（20261118-2319，首轮手测反馈）

1. **Backspace/Delete 失效**：根因是默认键绑定（bindings/mod.rs Backspace 家族 `\x7f`、Delete `\x1b[3~`）在 bindings 层先于输入栏分支消费了按键。新增 `BindingMode::INPUT_BAR`（bitflags 空位 0b1000_0000），`BindingMode::new(mode, search, input_bar)` 三参化；Backspace（plain/Alt/Shift/Ctrl）与 Delete 的默认绑定加 `~INPUT_BAR` 排除。输入栏分支同时完善 Backspace 家族：plain/Shift 删字符，Ctrl/Alt 删词（readline 语义）
2. **尺寸**：输入栏高度改为 **6 个终端行高**（`sugarloaf.compute_cell_metrics` 精确取 cell 高），字号为**终端字号 2 倍**；metric 经 `InputBar::update_metrics` 在 Screen::new / update_config / change_font_size（Ctrl+= 等运行时改字号）三处刷新，margin.bottom 随动并触发 PTY resize
3. **视觉**：去掉整条不透明黑底；改为预留带内浮动圆角面板——内部填充**共用窗口背景色**（`last_window_bg` 回退主题背景），四周 **4px 半透明厚边框**（锁定态更暗）着重强调；顶部 1px 分隔线移除
4. **连带修复**：底部锚定的 hint 链接提示条（draw_hint_tooltip）加 `bottom_inset`，抬到输入栏上方避免被面板遮盖

验证：tapterm 305 测试通过、clippy/fmt 干净；`utils::padding_bottom_from_config` 已删除（高度动态化后废弃）。待用户手测：退格/删除、6 行高度与 2 倍字号观感、边框透明度、vim 锁定态边框变暗。

### 修复轮次二（20261119-0949，二轮手测反馈）

1. **背景仍显黑色 → 全透明**：原实现"共用背景"是内层填充窗口背景色（不透明 quad），主题背景/背景图被盖住。填充环无法"挖孔"，改为 **4 条边框矩形**（上/下/左/右各 4px 半透明）构成边框，**中心完全不留自己的绘制**——窗口背景/背景图直接透出。render 签名去掉 window_bg 参数
2. **光标不闪烁/消失（尤其回车后）**：根因是原 `schedule_render_on_route`（RenderRoute 事件）在 application.rs L522 被 `is_event_based()` 门控，非 event 策略下唤醒帧为空操作，光标冻结在随机相位（有时恰好灭相位=消失）。改骑终端光标闪烁同款通道：render 末尾 `context_manager.blink_cursor(500)` → `BlinkCursor` 事件 → `Topic::CursorBlinking` 定时器 → `CursorBlinkingChangeOnRoute`（**无策略门控**，置 `CursorDamage::CursorOnly`（含 dirty）+ request_redraw）→ 下一次 render 再自续。每帧自续、双策略可靠；锁定态不续（无光标无可动画）
3. **↑↓ 翻历史输入 "OA"**：根因与退格同病——普通方向键（`\x1b[A..D`）与 APP_CURSOR 组（`\x1bOA..D`、Home/End `\x1bOH/F`）默认绑定在 bindings 层先于输入栏分支消费；zsh zle 开 smkx 后 ↑ 被编码 `\x1bOA` 直发 PTY 而行编辑器无内容，屏幕显示字面 "OA"。两组绑定（L771-774、L681-692）全部加 `~BindingMode::INPUT_BAR`，方向键/Home/End 在输入栏激活时归输入栏（↑↓ 历史、←→ 移动、Home/End 行首尾）

连带清理：删除 `InputBar::next_wake_in`（机制更换后废弃）、`BORDER_RADIUS`；恢复 `is_locked()` getter（render 末尾续帧条件使用）；Screen::new 中被遮蔽的 `padding_y_bottom` 初始绑定删除。

### 修复轮次三（20261119-1011，pane 边框与圆角配置）

**需求**：pane 加输入栏同款边框、圆角、更厚（约 2mm/5-10px），可配置自行调整。

- **配置**：复用既有 `[panel]` 段——`border-width` 默认 2.0 → **6.0**，`border-radius` 默认 0.0 → **10.0**（此前 radius 被解析但从未使用）。输入栏与 pane 边框共用这两个值，永远"同款"；热重载即时生效（Renderer 重建即读取）
- **共享圆角描边助手** `renderer::draw_rounded_frame`：4 条边矩形 + 4 段 corner arc（sugarloaf.arc，中心线半径 = R - t/2 使描边带落在 [R-t, R]；角度约定 0°=东/90°=南，y 向下）。中心零绘制保持透明——填充环无法挖孔。半径钳制到 min(w,h)/2，radius=0 退化为直角
- **pane 边框**：替换旧的扁平分隔线（`get_panel_borders`/`create_border` 删除，`walk_separators` 保留供边框拖拽命中测试）；renderer.run 中按当前 tab 每个 panel 的 `layout_rect`+scaled_margin 画圆角半透明边框，**焦点 pane 用强色（BORDER_COLOR），其余 pane 用暗色（LOCKED_BORDER_COLOR）**，单 pane 也画
- **输入栏**：render 改收 border_width/border_radius 参数（来自 `[panel]`），删除固定 BORDER_STROKE；颜色常量改 pub(crate) 与 pane 共享

已知取舍：边框叠加在终端内容之上（pane 内容铺满 panel box，无内缩带），半透明保持可读；嫌宽可调小 `border-width` 或调大 `[panel] padding`。corner arc 批次固定 order 0（sugarloaf arc API 无 order 参数），位于未聚焦蒙层（order 3）之下，与旧分隔线行为一致。

验证：tapterm 304 / tap-backend 222 测试通过（分隔线渲染测试随特性删除，命中盒测试改从 border_config 读宽）、clippy/fmt 干净。待用户手测：pane 圆角厚边框观感、焦点/非焦点明暗、`[panel] border-width / border-radius` 热调、输入栏同款联动。

### 修复轮次四（20261119-1017，输入栏宽高可配置、居中）

新增 `[input-bar]` 配置段（与顶层 `enable-input-bar` 并列）：

```toml
[input-bar]
width = "60%"    # 或像素数值，如 900；默认 "100%"（整宽）；水平居中
height = 200     # 或百分比字符串，如 "25%"；不配置则维持 6 终端行 × 2 倍字号
```

- **SizeSpec**（`tap-backend/src/config/input_bar.rs`）：裸数字=逻辑像素、`"60%"` 字符串=窗口百分比（0-100 钳制，缺 `%` 报错）；实现 Deserialize/Serialize（Config 需序列化），4 个 serde 测试
- **宽度**：纯渲染层——`panel_geometry` 按窗口宽解析并**水平居中**，超宽钳制到预留带；100% 与旧行为一致
- **高度**：`height_spec`（None=6 行默认/Px/Percent），`resolve_height` 统一解析（24px 下限防误配抹掉输入栏）；百分比模式挂入 `screen.resize`（`refresh_height` 变化时同步所有 grid 的 scaled_margin.bottom 再 relayout，窗口缩放实时跟随）；像素/默认模式仅配置与字号变化时刷新
- **热重载**：update_config 的 take/restore 补 `set_size`，改宽高即时生效不丢输入

### 修复轮次五（20261119-1034，pane 内间距生效，字符不再压边框）

**问题**：`[panel] padding` 此前只进 taffy 样式不内缩内容——apply_taffy_layout 把 `dimension.margin` 清零、grid 从 panel 盒边缘起画，字符与边框重叠。

- **padding 真正成为内容内缩**：`apply_taffy_layout` 将 `dimension.margin` 设为 `[panel] padding`（此前清零）→ `compute()` 从盒尺寸扣除 padding 计算行列；screen 发射的 grid 原点加 `padding × scale` 偏移（PanelFrame 新增 `pad_left_px/pad_top_px`）。所有路径（创建/resize/配置/字号）经 apply_taffy_layout 自动生效，PTY 行列随动
- **默认 padding 5 → 12**：避开默认 6px 边框 + 呼吸空间；`[panel] padding = [n]` 或 `[top, right, bottom, left]` 可调（margin 仍是 pane 之间的外间距，row-gap/column-gap 亦可用）
- **连带**：flex 收缩比例测试容差加 1% 相对项——taffy flex 分配在大 padding + 极端分屏比例下有随 padding 缩放的残差（探针实测：6:1 分屏半高窗口下小 pane 偏 +3.4px），原 1.5px 绝对容差按旧 padding=5 标定；试验过 shrink 权重改 border-box 基准与 min_size=0 均无效（更差），判定为 taffy 内部分配行为

### 修复轮次六（20261119-1158，未聚焦 pane 改为背景变暗，移除蒙层）

**问题**：未聚焦 pane 的低透明度黑色蒙层（order=3 overlay rect）盖在字符之上（与边框压字同病），且只盖网格内容区、底部留空。用户方案：移除蒙层，未聚焦 pane 直接**背景变暗**，字符保持全对比度。

- **移除蒙层**：renderer.run 的 unfocused overlay 块删除；`unfocused-split-opacity` / `unfocused-split-fill` 配置保留，语义改为背景暗度（fill 未设置时向黑色混合）
- **背景变暗**：`Renderer::unfocused_split_dim()` 暴露 `(factor, tint)`；screen 行发射时对未激活面板的 CellBg 逐格烘焙——默认背景格（alpha=0，透出窗口背景）填充半透明 tint，显式背景格向 tint 混合。焦点切换经 `has_active_changed` 强制整面板重建，烘焙态不滞留
- **优点**：字符不再被任何层覆盖；暗色严格贴合单元格区域（无底部留空）；padding 带仍为窗口背景、由暗色边框（LOCKED_BORDER_COLOR）框住，视觉统一
- 已知取舍：`window.opacity < 1` 的透明窗口下未聚焦 pane 的默认格变为半透明 tint 填充（此前蒙层同样改变观感）；行未被重建时烘焙不实时——由焦点切换强制全量重建保证

### 修复轮次七（20261119-1246，彻底移除未聚焦背景变暗，焦点指示仅靠边框明暗）

**用户决策**：背景变暗只覆盖单元格区域、pane 底部（padding + 不足一行余量）留亮缝，铺不满整个 pane；与其继续修（padding_extend 外扩是无界的，会渗入相邻 pane），不如整体去掉——**定位当前 pane 由边框明暗承担已足够**（焦点 pane 强边框 BORDER_COLOR、其余暗边框 LOCKED_BORDER_COLOR）。

- 删除全部背景变暗机制：screen 的 dim_cell_bg 烘焙块与 update_config 重烘焙刷新；Renderer 的 unfocused_split_dim getter 与字段
- 配置项同步移除：`[navigation] unfocused-split-opacity` / `unfocused-split-fill`（含 platform CLI 覆盖与加载钳制）。旧配置写了这两个键也不报错（serde 忽略未知字段）
- 未聚焦 pane 的视觉表达现为：暗色边框 + 空心光标，内容区原样

验证：tapterm 306 / tap-backend 226 测试通过、clippy/fmt 干净。待用户手测：分屏后未聚焦 pane 无任何暗层、边框明暗区分焦点。

### 修复轮次八（20261119-1654，锁定判定回归「仅编辑锁定」，SSH 会话不再锁死）

**问题**：SSH 登录远程机器后输入栏一直处于锁定态。根因：本地 shell 带 OSC 133 集成，`ssh host` 作为命令执行发出 `C` → 输入区置 `Running`；远程 shell 无集成、永不发 `A` → 输入区整个会话卡在 `Running`，锁定判定 `!at_prompt() || ALT_SCREEN` 永真。这是「命令运行中锁定」规则（原为保护 sudo 密码等交互输入直通）的连带后果，并非针对 SSH 的设计。

**用户决策**：回归最初约定——只有编辑类全屏程序（vim/vi/nano 等）进入限制状态；SSH 与命令运行期输入栏保持可用。

- **screen/mod.rs**：删除 `input_bar_locked`，`input_bar_active` 仅判 `ALT_SCREEN`；render 前 `set_locked` 同步简化为 alt_screen 一值
- **tap-vt**：`InputZone` 枚举、`input_zone` 字段、`prompt_start`/`command_start` 的 zone 置位、`at_prompt()` getter、`osc_133_input_zone_tracking` 测试整体移除（zone 失去全部消费者；OSC 133 程序状态上报与 `command_started_at` 时钟不受影响）

**行为连带变化（需知悉）**：sudo 密码提示、ssh 口令登录等非全屏交互输入，现在统一进输入栏缓冲（回显在输入栏内），提交后按相邻去重规则写入本地历史库——此前 zsh/fish 下走锁定直通不回显；REPL 的行为也与降级模式归一。介意者临时 `enable-input-bar = false`（热重载即时生效）。

验证：tap-vt 694（-1 为删除的 zone 跟踪测试）/ tapterm 332 测试通过、clippy/fmt 干净。待用户手测：ssh 登录后输入栏可用（整行发送远程 shell）、vim/less/tmux 仍锁定、退出 ssh 回本地提示符正常、sudo/ssh 口令输入观感可接受。

### 修复轮次九（20261120-1442，Ctrl+C 按输入栏状态分叉）

**需求**：Ctrl+C 不再无条件「清空+直通」——输入栏有字符时只清空输入栏、不透传进 pane；输入栏为空时才直通（shell 中断）。

- **screen/mod.rs** `process_input_bar_key` 的 Ctrl 分支 `"c"` 臂：先查 `input_bar.is_empty()`——空则 `return false`（字节落共享输入路径，直通 PTY，广播开启时照常扇出）；非空则 `clear()` 并 `return true`（完全消费，无 SIGINT，提示符重绘由输入栏自己承担）
- **input_bar.rs**：新增 `pub fn is_empty()`（`buffer.is_empty()`；preedit ghost 不计入——IME 组合态由系统持有，本地清不掉）

行为对照：清空旧半行不再顺带打断 pane 里正在跑的命令（如 Ctrl+C 只想作废打错的半行）；要中断仍在运行的前台命令，先空栏（或清空后再按一次）。Ctrl+D/Z/L 等其余 Ctrl 组合不受影响，仍无条件直通。

验证：tapterm 375 测试通过；clippy 仅存量 `manual_slice_fill` 告警、fmt 仅有全仓 rustfmt 工具链风格漂移（均与本次无关，改动文件无告警）。待用户手测：有字符 Ctrl+C 只清栏不打断、空栏 Ctrl+C 正常中断 ping 等前台命令。

## 已知限制

- Tab 补全、Ctrl+R 等依赖 shell 自身行编辑的交互不可用（shell 仅在回车后收到整行，等同快速粘贴）；远程 shell（ssh）的 Tab 补全结果与输入栏缓冲脱节
- REPL 类程序（python/irb 等非全屏）按键进输入栏，程序自身行交互（Ctrl+R 检索等）不可用——建议此类场景临时 `enable-input-bar = false`（热重载即时生效）
- 密码提示（sudo、ssh 口令等非全屏交互）：密码明文进输入栏缓冲、提交发送并写入本地历史库（相邻去重）——介意可临时 `enable-input-bar = false`
- shell 开 kitty REPORT_ALL_KEYS_AS_ESC 时 Enter 仍发 `\r`（非 CSI u）
- 上/下键在输入栏激活时是历史翻阅，不再滚动回滚区（用 Shift+PageUp 等滚动绑定）
