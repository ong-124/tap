# 修复 input-bar 配置节不生效

## 背景

用户在 `~/.config/tap/config.toml` 中配置 `[input-bar] width = "60%"`、`height = 200` 后输入栏宽度无变化；同时怀疑 `[panel] border-width / border-radius` 未生效。

## 根因

- `[input-bar]`：`Config` 结构体字段 `input_bar` 缺少 `#[serde(rename = "input-bar")]`（tap-backend/src/config/mod.rs），serde 只认下划线键名 `input_bar`；而 Config 未启用 `deny_unknown_fields`，连字符节 `[input-bar]` 被静默忽略，整体回落默认值（width=100%、height=六行终端行高）。文档注释与邻近的 `enable-input-bar` 均为连字符风格，属遗漏 rename 的 bug。
- `[panel]`：节名与字段名一致、`border-width`/`border-radius` rename 正确，实际一直生效（热重载时 `Renderer::new(config)` 重建亦会刷新）；只是默认 6.0/10.0 → 8.0/12.0 视觉差异小（输入栏圆角描边 + 分屏 pane 圆角边框各加粗 2px），不易察觉。

## 实施

- `tap-backend/src/config/mod.rs`：`input_bar` 字段补 `rename = "input-bar"`，与全项目 kebab-case 配置键风格统一。
- 新增回归测试 `config::tests::test_input_bar_section_uses_hyphenated_key`：验证空配置回落默认值、连字符节 `[input-bar]` 的 width/height 正确解析（修复前该节被静默忽略）。

## 验证

- `cargo test -p tapterm -p tap-backend --lib config::`：96 passed（含新测试）。
- 重新构建 `target/release/tap`（x11）；待用户重启 tap 实测：输入栏宽度应变为窗口 60% 居中、高度 200px 逻辑像素。
