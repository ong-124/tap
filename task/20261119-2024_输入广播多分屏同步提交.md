# 任务：输入广播（多分屏同步提交）

## 背景与目标

运维场景经典需求（tmux `synchronize-panes`、XShell/FinalShell 广播）：一条命令同时发到多个会话。tap 已有分屏/标签与底部输入栏，广播在其上的天然形态 = **提交级 fan-out**——输入栏架构下逐键本来就不进 PTY，广播无需（也不应）转发按键流，只转发提交结果，天然规避了 tmux 广播把控制键灌进 vim 的破坏性场景。

## 设计（草案，v1 收敛）

- **形态**：广播开关 toggle（键位待定，候选 `<leader>`+B，需对照 `docs/20261118-2150_快捷键清单.md` 避让）；开启期间输入栏提交 → `line + \r` 依次 `send_write` 到 scope 内全部 pane；关闭即恢复单发
- **v1 scope**：当前标签的全部分屏（含焦点 pane）。扩展项（全部标签/勾选集合）列为后续，不进 v1
- **安全边界**：仅发到「可用」pane——非 ALT_SCREEN 锁定（向 vim/less 发整行文本有破坏性）；锁定 pane 跳过。提交时若发生跳过，输入栏瞬时提示跳过数（防「以为发了其实没发」）
- **最小可见性**：广播开启期间输入栏提示符前加标识（如 `>>` 前缀或 `❯` 变色），关闭复原；无持久化配置，会话级状态
- **与历史的交互**：广播提交记一条历史（当前焦点 pane 的 cwd），不按 pane 重复记

## 开放点（实施前定）

- 开关键位（查快捷键清单避让；toggle 需要能在输入栏聚焦时触发，注意路由优先级——输入栏聚焦时 mods 组合键仍走全局绑定）
- 多 pane cwd 不同时补全建议用谁的（v1：仍按焦点 pane，广播只影响提交目标）
- 将来可选：与 OSC 133 AtPrompt 真值联动（仅发提示符态 pane，见 20261119-2024 任务「明确不动」条的将来项）

## 验收

- `cargo test` 全绿（含路由纯函数测试：广播开关下 submit fan-out 目标集合计算），clippy/fmt 干净
- 手测（用户执行）：三 split 开广播一次提交三处执行；其中一个 pane 开 vim 后提交，该 pane 不被灌入、提示跳过 1；关闭后单发恢复；↑ 历史只多一条

## 修复轮次一（20261119-2205，Ctrl+C 不随广播扇出）

**用户反馈**：4 个 pane 开广播跑 `ping`，Ctrl+C 只有焦点 pane 的 ping 退出，其余三个继续跑。

**根因**：v1 只扇出整行提交；Ctrl+C 走「清空输入栏 + 单发直通」路径（screen `process_input_bar_key` 的 Ctrl 分支），字节只进焦点 pane。

**修复**：广播开启时 Ctrl+C 额外经 `broadcast_to_others(&[b'\x03'])` 扇出到其余可用 pane（焦点 pane 仍走原直通路径，不双发）；锁定 pane 静默跳过（SIGINT 灌进 vim 有破坏性，且停广播命令不需要它）。**仅 Ctrl+C**——Ctrl+D（EOF 关 pane）、Ctrl+Z 等保持单发。顺带把提交处内联的 pane 收集重构为 `broadcast_panes()` 共享 helper。

- 行为变化：广播开启时 Ctrl+C = 清空输入栏 + SIGINT 扇出；广播关闭时行为不变
- 验证：tapterm 376 通过，clippy 0 告警，fmt 干净；待用户复测（4 pane 广播 ping 后一次 Ctrl+C 全停）

## 修复轮次二（20261119-2230，改忠实广播，用户拍板）

**用户反馈**：修复轮次一「仅 Ctrl+C 扇出、Ctrl+D/Z 单发防呆」不对——广播是用户显式开启的模式，「用户对自己的输入负责，我们忠实的广播」。

**重设计（tmux synchronize-panes 语义）**：广播开启时，一切发往焦点 pane PTY 的终端输入字节原样发到当前标签**全部** pane，不筛选、不提示——按键按下/释放（kitty 事件）、Esc、任意控制组合（含 Ctrl+D/Z）、粘贴到 PTY、整行提交。实现收敛为单一汇聚点 `send_input_bytes()`（按键直通、key-release、粘贴、提交四处接线），比之前的分散扇出更简单。

随之删除：锁定 pane 跳过与跳过数提示（notice 机制整体移除）、`broadcast_recipients` 纯函数及 3 测试（无筛选后合同平凡化）、`broadcast_panes`/`broadcast_to_others` helper、Ctrl+C 特例分支（字节走共享路径自然扇出）。鼠标事件保持单发（非键盘输入）。

- 行为边界：焦点 pane 在 vim（alt-screen）时输入栏锁定、按键全部直通 → 广播开启时同样全量扇出（vim 键进其他 pane 属用户责任）；`>>` 提示符标识保留
- 验证：tapterm 373 通过，clippy 0 告警，fmt 干净；待用户复测（4 pane 广播 ping → Ctrl+C 全停；Ctrl+D 广播会关掉全部 shell——用户自担）
