# ssh 会话裸词远程 cwd 锚定（设计）

## 背景

远程路径补全（task/20261120-1718）落地后的已知边界：ssh 侧信道每次是 sshd 新 spawn 的 bash，cwd 恒为远程 home，而交互 shell 的真实 cwd 对它不可见。裸词（`cd Doc<Tab>`、`nginx<Tab>`）与相对目录头词因此锚定远程 home——用户 `cd /var/log` 之后再 Tab，候选列错目录。

**问题本质**：tap 与远程交互 shell 之间没有任何 cwd 通道。解决思路是找到至少一条可信的远程 cwd 来源，按可信度分层锚定。

## 现状事实（设计依据）

- `Term.current_directory`（tap-vt crosswords/mod.rs#L591）生产写入点**只有 OSC 7 handler**（`set_current_directory`）；本地探测 `foreground_process_path` 是 `focused_pane_cwd`（screen/mod.rs#L1357）里的**实时调用**，不落盘。即：`current_directory = Some(_)` ⟺ 该 pane 收到过 OSC 7 且未清空。
- OSC 7 是输出流转义序列，远程 shell 发的会穿过 ssh 连接被 tap-vt 解析。最常见的 `file://$PWD` 形式（host 为空）被 `host_is_local` 放行，值即远程路径真值；`file://$(hostname)/...` 形式被拒收（osc.rs#L281，上游语义：非本机目录不报为己有）。
- ssh 会话内 `focused_pane_cwd` 的 probe 兜底读到的是**本地 ssh 客户端进程的 cwd**（≈tap 本地 cwd），当远程 cwd 用是错位值——ghost 建议（`set_focus_cwd`）与提交落盘 cwd 元数据当前都在消费它。
- 多 pane 多 ssh 到同主机时，侧信道无法从「聚焦 pane」定位到「远端哪个 shell」——这是歧义根源。

## 设计：三梯度锚定

优先级从高到低，高梯度有值即用，逐级回落：

### 梯度一（T1）：pane 的 OSC 7 值直接作 anchor

ssh 会话内，把 `current_directory`（OSC 7 专属来源）组装为 `Sources` 新字段 `session_remote_cwd: Option<String>`，经 `route()` 传入 `DynamicRequest::RemotePaths { host, word, anchor }`。远程脚本 `cd` 到 anchor 再跑现有 `compgen` 管道——相对词全部正确。

- anchor 为远程 shell 自己报的 pwd，是聚焦 pane 的精确真值，且免去远端 /proc 遍历。
- 残留风险天然防御：本地 shell ssh 前发过 OSC 7、远程不再发时，`current_directory` 残留本地旧值——远端 `cd` 该路径失败（`cd ... 2>/dev/null || true`），脚本留在 home，等于回落 T3。
- 已知限界：`file://$(hostname)` 形式仍被既有 host 校验拒收（tap-vt 不动，尊重上游"非本机目录不报为己有"的保护），这类 shell 落 T2。

### 梯度二（T2）：远程脚本内 /proc 探测

anchor 缺席时，脚本先探测再 compgen。探测谓词：同 uid 可读、`comm` ∈ shell 表（bash/zsh/fish/nu/ksh/tcsh/dash/mksh）、`fd/0` 指向 `/dev/pts/*`（交互会话；远端 tmux pane 的 pty 也是 pts，覆盖 tmux 内场景）、多候选取 `/proc/pid/stat` 字段 22（starttime）最大者 = 最新启动的交互 shell。拿到 cwd 后 `cd`，再 compgen；探测/`cd` 失败留在 home（= 现行为）。

脚本骨架（并入 build_command 的 RemotePaths 分支，stat 解析需先剥 `pid (comm)` 头避免 comm 含空格错位）：

```bash
probe() {
  best=""; bs=-1
  for d in /proc/[0-9]*; do
    p=${d##*/}; read -r c < "$d/comm" 2>/dev/null || continue
    case $c in bash|zsh|fish|nu|ksh|tcsh|dash|mksh) ;; *) continue ;; esac
    case "$(readlink "$d/fd/0" 2>/dev/null)" in /dev/pts/*|/dev/tty[0-9]*) ;; *) continue ;; esac
    cwd=$(readlink "$d/cwd" 2>/dev/null) || continue
    raw=$(cat "$d/stat" 2>/dev/null) || continue
    raw=${raw#*) }; set -- $raw; st=${19}
    [ -n "$cwd" ] || continue
    [ "${st:-0}" -gt "$bs" ] && { bs=$st; best=$cwd; }
  done
  printf '%s' "$best"
}
a="<anchor 或 probe 结果>"; cd "$a" 2>/dev/null || true
<现有 compgen 管道不动>
```

主流程统一为「cd 后跑现有管道」：绝对/`~` 词不受 cd 影响，裸词与相对头词按 anchor 解析，语义自洽。

### 梯度三（T3）：远程 home 兜底

探测与 anchor 都不可用时的现行为，保持不变。

### 顺带修正（同一落点，控制范围）

ssh 会话内 `sources.cwd` 的消费错位：组装 `Sources` 时（screen/mod.rs tab_complete 处）ssh 会话内改用 OSC 7-only 值（`current_directory` 字段直读，不走 probe 兜底），ghost 的 `set_focus_cwd` 与提交落盘 cwd 元数据随之记录真值或空。本地 pane 行为零变化。

### v2 演进方向（不在本任务）

多 pane 多会话时 T2 的「最新启动」启发式可能选中另一个 pane 的 shell（候选列错目录，可见可覆盖，无害）。精确方案：本地从聚焦 ssh 客户端进程查 TCP 源端口（ss/lsof），远端遍历 `/proc/*/environ` 匹配 `SSH_CONNECTION` 第二字段锁定该 pane 的远端 shell。仅多会话用户受益，成本较高，延后。

- tap-vt：不动。

## 已知边界（记录不改）

- `file://$(hostname)` 形式 OSC 7 被拒收 → 落 T2/T3；远程 shell 默认都不发 OSC 7 → T1 常空。
- 远端无 bash（busybox）→ 现有 RemoteCommands/RemotePaths 既有假设，一并失效。
- probe 选错 pane（多会话）→ 候选可见可覆盖；v2 解决。
- 容器/hidepid 导致 /proc 不可读 → probe 空 → 回落 home。

### 修复轮次一（20261121）：ssh 相对路径补全锚错目录

- 用户手测反馈：ssh 会话内相对路径无法回显/锚定，绝对路径正常。定位：本地 shell 集成在 ssh 启动前发的 OSC 7（本地 cwd）驻留 `current_directory`，远端 shell 无集成永不刷新；T1 anchor 拿到的是本地陈旧值，远端 `cd` 失败静默留 home（T3），相对词/裸词全部锚错目录，绝对词自带锚不受影响——脚本本地实测复现。设计段「残留风险天然防御……等于回落 T3」低估了该路径的常态性：本地集成默认开启 + 远端默认无集成 = 每次 ssh 会话必现。
- completion.rs `build_command`（RemotePaths）：锚定链由「anchor 空才 probe」改为「`cd "$a"` 失败即 probe、probe 再失败留 home」（`cd ""` 同样失败，空 anchor 行为不变）；`anchor` 字段 doc 与脚本注释同步（anchor 为 None **或 cd 失败**均触发 probe）。
- screen/mod.rs `submit_input_bar_line`：交互 ssh 提交（`interactive_ssh_dest` 命中）时经 `set_current_directory(None)` 清除 pane 的陈旧本地 OSC 7——会话内历史作用域/落盘元数据按设计段既有语义退化为「真值或空」（host-only，直到远端自己报值），补全 anchor 变 None 直走 probe；ssh 断开后本地 shell 下一个提示符的 OSC 7 自然恢复。`ssh host` 行本身仍按本地作用域落盘（提交时 ssh 尚未成为前台进程），清除置于作用域快照与落盘之后。
- 测试：`remote_paths_script_probes_without_an_anchor` 增补 `cd` 失败回落 probe 的脚本断言。
