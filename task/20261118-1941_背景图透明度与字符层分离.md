# 任务：背景图透明度与字符层分离

## 背景与目标

当前设置背景图片透明度后，观感上字符也被"淡化"，疑似图层/透明度作用范围问题。目标：背景图的透明度/暗化只作用于背景图层，字符层渲染不受影响，保持文字对比度与可读性。

## 需求细节

- 背景图透明度（或暗化、降饱和）独立可控
- 字符前景色/亮度不受背景图透明度参数影响
- 调节后终端文字依旧清晰可读

## 设计调研（20261118 架构调研结论）

- 配置：`tap-backend/src/config/window.rs` L205 `background_image: Option<ImageProperties>`
- 加载与透明度：`sugarloaf/src/sugarloaf.rs::set_background_image` L498；L531-537 将 opacity 乘入像素 alpha 通道，上传纹理时烘焙
- 绘制顺序（wgpu `renderer/mod.rs::render` L1864，L1898 背景图最先绘制；Metal 路径 L2241-2290 有 z 顺序注释）：
  bg fill → 背景图 → kitty BelowBg → grid bg → BelowText → grid 文本 → AboveText → 富文本 overlay → UI 文本
- 理论上字符在背景图之上，opacity 只应影响图片；需复现确认"影响字符"的真实来源，可能的怀疑点：
  - cell 背景色（grid bg）以不透明色覆盖在背景图上，导致整体"透明感"不一致，观感上字符区域被压暗/淡化
  - 窗口级 opacity（window transparency）与背景图 opacity 混用，窗口整体透明导致字符也透明
  - 半透明像素混合时缺少背景基色，边缘发灰

## 关键子任务

1. 复现问题并定位根因（确认 opacity 作用层级）
2. 背景图独立暗化/透明度处理，不影响字符渲染
3. 字符对比度验证

## 实施记录

### 根因分析（20261118）

复现路径推演 + 代码核实，确认"字符被淡化"的真实来源是 **wgpu / Vulkan 路径的绘制顺序错误**，而非 opacity 参数本身：

- `sugarloaf/src/sugarloaf.rs::render_wgpu` 与 `render_vulkan` 均先录制 grid 的 bg+text 两个 pass，之后才调用 `self.renderer.render()/render_vulkan()`
- 而背景图的绘制位于 `Renderer::render()/render_vulkan()` **内部最先**执行 —— 即整体顺序为：clear → grid bg → **grid 文本** → **背景图** → …
- 背景图管线为预乘 src-over 混合（`One / OneMinusSrcAlpha`）：image opacity = 0.7 时，字符先画好、再被 70% 不透明度的图盖上去，观感即"字符被淡化"；opacity = 1.0 时字符会被完全遮住
- Metal（macOS）路径顺序正确：bg fill → 背景图 → grid bg → grid 文本（任务文档调研阶段记录的"理论顺序"仅 Metal 成立）

次要问题：`frontends/tapterm/src/renderer/mod.rs` 中配置背景图时曾把窗口基色强制为 `Color::TRANSPARENT`（RGB=黑），在 `opacity=1` 的不透明窗口上退化为黑色 —— 图像向黑色混合而不是向主题背景色混合。

### 修复内容（20261118）

1. **背景图移到 grid 之前绘制**（核心修复）
   - `sugarloaf/src/renderer/mod.rs`：新增 `Renderer::render_background_image_wgpu` / `Renderer::render_background_image_vulkan`，将背景图绘制从 `render()` / `render_vulkan()` 中拆出
   - `sugarloaf/src/sugarloaf.rs`：`render_wgpu` / `render_vulkan` 在 grid bg/text pass 之前调用上述方法；`Renderer::render*` 内部不再画背景图（并修正早退条件）
   - 修复后 wgpu/Vulkan 顺序与 Metal 一致：clear/基色填充 → 背景图 → grid bg → grid 文本 → 富文本/UI 覆盖层
2. **背景图下的基色改为主题背景色**
   - `frontends/tapterm/src/renderer/mod.rs::Renderer::new`：删除 `Color::TRANSPARENT` 特判；背景图模式下窗口基色保持主题背景色（`window.opacity=1` 时不透明）
   - 效果：`background-image.opacity` 语义变为"图像与终端背景色的混合比例"，只作用于图像层；字符画在图像之上，前景色/亮度不受该参数影响
3. **字符对比度验证方式**（用户自测）
   - 配置 `[window] background-image = { path = "...", opacity = 0.3 }`：字符应与无背景图时完全一致（全对比度），图像呈 30% 混合主题背景色
   - 调整 opacity 0~1：只有图像明暗变化，字符无变化
   - 默认背景 cell 仍为 `(0,0,0,0)` 直通（不遮挡图像）；SGR 显式背景色的 cell 按预期覆盖在图像之上

4. **设置默认背景图片**（用户追加需求）
   - `tap-backend/src/config/window.rs`：`background_image` 增加 serde default `default_background_image()`，默认指向仓库内 `background/t013c2f41e0a5020acc.jpg`（opacity = 1.0）
   - `frontends/tapterm/src/screen/mod.rs`：`Screen::new` / `update_config` 中空 path 视为"无背景图"，用户可用 `background-image = { path = "" }` 退出默认图，不会弹出加载失败警告
5. **编译验证**：`cargo check -p sugarloaf --features wgpu`、`cargo check -p sugarloaf`（默认/Vulkan 路径）、`cargo check -p tapterm` 全部通过；仅存量 manifest unused-dep 警告，与本次改动无关
