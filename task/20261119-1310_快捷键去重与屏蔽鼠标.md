# 任务：快捷键去重与屏蔽鼠标

## 背景与目标

`[` / `]` 同时绑定了标签切换与分屏切换，语义重复且易混淆。目标：

1. 去掉 tab 和 pane 的 `[` / `]` 循环切换
2. 标签页统一用 Ctrl+Tab（下一个）、`<leader>`+Tab（上一个，即 Ctrl+Shift+Tab）、`<leader>`+1…8（切第 n 个）、`<leader>`+9（最后一个）
3. 分屏焦点改为 vi 风格方向切换：`<leader>`+H/J/K/L（左/下/上/右，仅在当前标签内移动）
4. 鼠标默认屏蔽（tap 重度使用键盘）：无现成配置，新增 `disable-mouse`，默认 true
5. 同步更新快捷键清单（全量）

## 设计

- 新增 `Action::SelectSplitDirection(SplitDirection)`（单变体带方向，优于 4 个平级变体）；配置字符串 `selectsplitleft` / `selectsplitdown` / `selectsplitup` / `selectsplitright`
- `layout/mod.rs` 新增 `SplitDirection` 枚举与 `select_split_direction()`：基于各 pane 的 `layout_rect` 几何，候选 = 完全位于目标方向一侧的 pane；垂直于移动方向的投影重叠最大者胜，平手取距离最近者；无候选则不动（不循环、不跨标签）
- 三平台 `platform_key_bindings`：删除全部 `[` / `]` 默认绑定；Linux/Windows 增 `prefix+1…9` 切标签（Shift 按下时键匹配走 `key_without_modifiers()`，`ctrl+shift+1` 可直接命中数字键）；三平台 splits 块增 `prefix+h/j/k/l`（macOS 无 Shift+数字问题，保留 Super+1-9）
- 鼠标屏蔽：`Config.disable-mouse`（serde `disable-mouse`，默认 true，随热重载生效）；`application.rs` 窗口事件入口直接丢弃 `MouseInput` / `CursorMoved` / `CursorLeft` / `MouseWheel` / `Touch`，不进入任何路由（不选词、不拖分隔线、不向 PTY 转发鼠标事件）
- 保留 `selectnextsplit` / `selectprevsplit` action（命令面板 + 用户自定义绑定仍可用），仅移除默认键

## 关键子任务

1. `SplitDirection` + `select_split_direction` 几何实现与单测
2. 新 Action + 三平台默认绑定改造（去 `[` / `]`、leader+数字切标签、leader+h/j/k/l 切分屏）
3. action 链路打通（context manager 委托 + screen 分发）
4. `disable-mouse` 配置 + 事件层屏蔽
5. 编译 / 测试 / clippy / fmt 验证
6. 更新 docs/20261118-2150_快捷键清单.md（全量，含输入栏小节、鼠标小节）
7. 用户实测

## 修复轮次一（20261120-1419，disable-mouse 全盘禁用致选中/中键粘贴失效）

**用户反馈**：① 需要保留正常的鼠标选中与中键粘贴；② vi 模式无法将选中字符写入缓冲区，无法完成复制粘贴。

**排查**：

- ① `disable-mouse` 在 `application.rs` 窗口事件入口把 `MouseInput`/`CursorMoved`/`CursorLeft`/`MouseWheel`/`Touch` 五类事件整体丢弃，拖拽选中与中键粘贴一并失效。
- ② 用 xdotool 驱动真实 GUI 逐路验证：release 二进制上 vi 模式 motions 实时写 PRIMARY、`y` 双写 CLIPBOARD+PRIMARY 均正常（曾以临时 TAPDBG eprintln 插桩 debug 构建取证据后移除）。用户感知「写不进缓冲区」实为复合原因：中键粘贴被 ① 挡死（贴不出来即误以为没复制）；且选区若只覆盖行尾空白单元格（vi 光标停在提示符行尾时常见），`selection_to_string` 为空 → `copy_selection` 静默不写，属既有空选区语义。
- 额外发现：即使非禁用模式，松开鼠标也只写 CLIPBOARD（且仅 `copy-on-select` 时），PRIMARY 永远是旧内容——X11 惯例「选中即入 PRIMARY、中键即贴」在鼠标路径上从未成立过。

**修复**（仅 `frontends/tapterm/src/application.rs`）：

1. 入口闸门收窄：`disable-mouse` 只丢 `CursorLeft`/`MouseWheel`/`Touch`；`MouseInput`/`CursorMoved` 放行到 handler 内的过滤分支。
2. `MouseInput` 增加 disable-mouse 最小路径：维护三键状态与多击计时（双击选词/三击选行保留）；press 先 `select_current_based_on_mouse` 焦点切换、左键走 `on_left_click`（选中起点），再 `process_mouse_bindings`（中键 PasteSelection 由此生效）；release 停掉选区滚动定时器。chrome/标签栏/滚动条/分隔线/Hint/PTY 鼠标上报路径全部不经过。
3. `CursorMoved` 增加 disable-mouse 分支：仅在左/右键按住时更新选区（含边缘自动滚动定时器），其余悬停工作（chrome、边框、Hint、光标图标、mouse report）全跳过。
4. X11 惯例补齐（两个 release 分支同步）：选区非空松开左/右键 → 始终 `copy_selection(Selection)`（PRIMARY），`copy-on-select` 时另写 CLIPBOARD。非禁用模式同样受益。

**验证**：tapterm 375 通过（tap-vt 的 `test_single_capability_requests` 失败为干净 HEAD 上的预存在问题）；clippy 无新增告警（仅遗留上一任务 manual_slice_fill）；rustfmt 对改动文件干净；release 构建 + 真实 GUI 闭环：拖拽选中 → PRIMARY 更新 → 双击选词（"tap*"）→ 中键粘贴落盘 input-history，全通。
