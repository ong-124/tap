# 输入栏提示符换为西红柿 emoji

## 背景

用户反馈：广播模式 `>> ❯` 中 `>>` 后的符号显示为无法识别（豆腐）。

- 原符号：`❯` U+276F（HEAVY RIGHT-POINTING ANGLE QUOTATION MARK ORNAMENT），zsh/p10k 风格提示符。
- 豆腐根因有二：
  1. 默认字体 Fira Code SemiBold 无 U+276F 字形（本机仅 Nerd Font 系列覆盖）。
  2. sugarloaf `text.rs::shape_for` 按整条文本**首字符**解析字体（`font_resolve.entry((first_ch, ..))`）——广播时 prompt 串 `">> ❯"` 首字符 `>` 把整串钉死在 Fira Code，`❯` 必然豆腐；正常模式单字符 `❯` 走 fontconfig cascade discovery 理论上能落到 Nerd Font，但字体覆盖不可靠。

用户要求换成 tomato。

## 设计

- `PROMPT_SYMBOL`：`"\u{276F}"` → `"\u{1F345}"`（🍅 TOMATO），与项目西红柿图标主题统一；正常模式 `🍅`、广播模式 `>> 🍅`。
- 拆分绘制：广播 marker（`>> `，ASCII）与提示符（`🍅`）改为两次独立 draw，各自按首字符解析字体——`>> ` 走 Fira Code，`🍅` 走 fontconfig discovery → Noto Color Emoji（本机 `fc-list :charset=1f345` 确认覆盖），避免首字符机制把 emoji 钉死在等宽字体。
- 渲染链路确认可行：Linux discovery（`font/linux.rs` FcCharSet 单码点匹配）+ swash `select_color_bitmap`/`normalize_color_bitmap` CBDT 彩色位图 + Vulkan/wgpu 双图集（grayscale/color atlas），`is_color` 实例走原色不套 PROMPT_COLOR。

## 实施记录

- `frontends/tapterm/src/renderer/input_bar.rs`：PROMPT_SYMBOL 常量替换；prompt 绘制由 format! 拼串单次 draw 改为 marker/symbol 两段 draw 宽度累加（注释同步）。

## 验证

- cargo check / clippy（触碰文件无告警）/ fmt 通过；tapterm 387 测试通过；release 已重建。
- 待用户手测：正常模式与广播模式提示符显示彩色 🍅（广播 `>> 🍅`）；若系统无 emoji 字体则仍为豆腐（本机有 Noto Color Emoji）。
