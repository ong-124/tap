# 任务：纯键盘选择与复制（终端面板 vim 可视模式）

## 背景与目标

不借助鼠标、也不进入 vim 编辑器，直接在当前终端面板上用键盘完成文本选择与复制：类似 vim 的可视模式操作（v 开始选择、移动扩展选区、y 复制），选中内容可进剪贴板/缓冲区，配合鼠标中键（或绑定键）输出。

## 需求细节

- 键盘快捷（可挂在前缀键下）直接进入选择模式
- vim 风格移动：h/j/k/l、w/b/e、0/$、g/gg、Ctrl+d/u 等
- v 进入可视选择（字符级），V 行级选择（可选）
- y 复制选中内容到剪贴板；也可选中即入缓冲区
- 选中后中键（已有 PasteSelection 语义）或绑定键输出
- Esc 退出选择模式，回到普通输入

## 设计文档归档（20261118，原 .trae/documents/vi-visual-selection-copy.md）

### 差距调研明细

vi 模式已具备绝大部分能力（全套 motions、v/V/Ctrl+v/Alt+v 四种选区、移动自动扩展选区、y 复制、中键 PasteSelection），真正差距：

1. `y` 只写 CLIPBOARD 不写 X11 PRIMARY → 中键贴不出 y 的内容（`copy_selection` 调用点 screen/mod.rs L1107）
2. 选区变化不实时进 PRIMARY，无法「选中即中键输出」
3. Esc 只清选区不退 vi 模式（用户已确认两段式语义）
4. Ctrl+d/u 等滚动移动在 VI 模式下不扩展选区（与 h/j/k/l 不一致）；g/G 扩展了选区但渲染高亮不同步（既有 bug）
5. `{` `}` 段落移动（ViMotion::ParagraphUp/Down）已有实现未绑键

用户决策：Esc 两段式；**不加**新入口键（沿用 Alt+Shift+Space → v 两步）；实时写 PRIMARY + y 双写。

```rust
/// vi 模式下把当前选区实时同步到 PRIMARY（中键输出用）
fn sync_vi_selection_clipboard(&mut self, clipboard: &mut Clipboard) {
    let should = {
        let terminal = self.context_manager.current().terminal.lock();
        terminal.mode().contains(Mode::VI)
            && terminal.selection.as_ref().is_some_and(|s| !s.is_empty())
    };
    if should {
        self.copy_selection(ClipboardType::Selection, clipboard);
    }
}
```

### 明确不做

- 不加新入口键（用户确认）
- 不动 `toggle_vi_mode` 进出行为、不动鼠标选区流程

- 超大选区实时写 PRIMARY 的性能防御暂不做（常规选区毫秒级；观察后再定）
