## 背景

现有输入历史为 TSV 文本文件（`{config_dir}/input-history`，`ts\tcwd\tline[\texit]`），讨论中确认三个结构性问题：

1. **去重只做一半**：会话内仅相邻去重（`a b a` 留两条 a，重跑老命令不沉底），全局去重只在启动时内存内做一次，文件重复行堆积。
2. **归并有真实 bug**：cap 触发的 `rewrite()` 整文件 read-modify-write，并发窗口 append 丢失，且重编码写死 `ts: now, cwd: ""` 销毁保留条目元数据；`backfill_exit` 同样整文件重写存在竞态；exit 回填靠 `(秒级 ts, line)` 匹配，同秒重复提交有歧义。
3. **回显是扁平字符串 + 平行数组**：`history: Vec<String>` + `history_cwds: Vec<String>`，ts/exit 丢弃，无法支撑按目录回显。

根因：文本 TSV 当数据库用，append 可并发但一切修改都是 read-modify-write。

## 需求定稿（用户拍板）

- **按路径去重、按路径回显**：本地作用域 `(cwd, line)`；SSH 多一层，作用域 `(host, cwd, line)`。「明天到那个目录敲一下 ↑，昨天的命令就在」。
- **三表模型**（用户设计）：路径表、命令表（带使用次数）、路径-命令关系表，去重在三表各自进行，避免重复记录命令与路径。
- **回显策略**：作用域优先；当前作用域无历史时，用全局最频繁使用的命令兜底（频次数据来自命令表）。**严格两态**：作用域有历史时 ↑ 只走作用域内命令，走完即停回输入行；不接续兜底列表。
- **存储**：SQLite（rusqlite bundled），WAL + busy_timeout。
- **host 归一化**：ssh 目标经 `ssh -G` 解析 canonical HostName 后入库，按 dest 内存缓存，失败退原样。
- **远端无 OSC 7**（无 shell integration）：cwd 记 `''`，退化为按主机聚合。
- **exit 回填**：提交时 `RETURNING usages.id` 入队，OSC 133 `D` 到达按 id 精确 UPDATE，替换 `(ts, line)` 匹配。
- **无迁移义务**：架构变更，旧 TSV 不迁移不删除（忽略），开发阶段无向后兼容义务。

## 设计

### 数据模型

```sql
CREATE TABLE dirs (
  id   INTEGER PRIMARY KEY,
  host TEXT NOT NULL DEFAULT '',      -- '' = 本地
  cwd  TEXT NOT NULL DEFAULT '',
  UNIQUE (host, cwd)
);
CREATE TABLE commands (
  id   INTEGER PRIMARY KEY,
  line TEXT NOT NULL UNIQUE,
  uses INTEGER NOT NULL DEFAULT 1,    -- 全局终身次数（兜底排序）
  ts   INTEGER NOT NULL               -- 最近一次使用（次数并列决胜）
);
CREATE TABLE usages (
  id         INTEGER PRIMARY KEY,
  dir_id     INTEGER NOT NULL REFERENCES dirs(id),
  command_id INTEGER NOT NULL REFERENCES commands(id),
  ts         INTEGER NOT NULL,        -- 该目录最近一次使用
  uses       INTEGER NOT NULL DEFAULT 1,
  exit       INTEGER,
  UNIQUE (dir_id, command_id)
);
```

### 写入路径（提交，单事务）

1. `dirs` upsert → dir_id
2. `commands` upsert（conflict 时 `uses = uses + 1, ts = ?`）→ command_id
3. `usages` upsert（conflict 时 `ts = ?, uses = uses + 1, exit = NULL`）`RETURNING id` → usage_id 入 exit_pending 队列

### 回显路径

启动全量载入（JOIN ≤1 万条），内存按焦点 pane `(host, cwd)` 实时分桶：

- 作用域有历史：只回显该作用域命令，`ts` 降序
- 作用域无历史：全局 `commands` 按 `uses` 降序兜底

ghost suggestion 与 ↑ 浏览共用同一两态列表。cd 换目录即时重排，不回库查询。

### 作用域解析（提交与回显同一套）

| 场景 | host | cwd |
|---|---|---|
| 本地 pane | `''` | OSC 7 → /proc 探测兜底 |
| ssh + 远端 integration | `ssh -G` 归一化 host | 仅信 OSC 7（远端真值） |
| ssh + 远端无 integration | 同上 | `''`（按主机聚合） |

### 收尾配套

- trim：启动时单事务删 `usages` 超上限老记录 + 清无引用 `dirs`；`commands.uses` 终身计数不回收（规模 = 用过的不同命令数，天然有界）。
- 连接：进程内 `OnceLock<Mutex<Connection>>` 惰性打开，多窗口同进程共享；跨进程 WAL 兜底。
- 会话内 `a b a`：同作用域全局去重（移尾刷新 ts），与库语义一致。

## 实施记录

- **依赖**：workspace `[workspace.dependencies]` 增 `rusqlite 0.32.1`（bundled，libsqlite3-sys 0.30.1 静态编译），tapterm 引用。wasm 顾虑解除：本机仅装 linux target，libtap-wasm 不依赖 tapterm，无需门控。
- **input_history.rs 全量重写**（TSV → SQLite）：
  - 三表 schema（`dirs` / `commands` / `usages`，见设计节），`open_conn` 加 WAL + busy_timeout(500ms)；
  - `open_store`：DatabaseCorrupt 时删库文件（含 -wal/-shm）重建自愈；
  - 进程级 `OnceLock<Option<ParkMutex<Connection>>>`，首次使用时打开并 trim 到 1 万条；任何库故障降级 no-op（bar 回退会话内历史）；
  - `record(host, cwd, line, ts) -> Option<usage_id>`：单事务三连 upsert（dirs DO NOTHING / commands uses+1 / usages upsert RETURNING id）；
  - `load() -> Snapshot { entries: Vec<Entry>, frequent: Vec<String> }`：JOIN 全量按 ts 升序 + 全局频次池（uses desc，上限 255）；
  - `trim_on`：usages 留最新 cap、清孤儿 dirs、commands 终身保留；
  - `backfill_exit(usage_id, exit)`：按主键单条 UPDATE；
  - exit 队列 payload 改 `(ts, usage_id)`，`exit_target` 归属逻辑不变；
  - Entry 字段改 `{host, cwd, line, ts, exit}`。
- **completion.rs**：`normalize_ssh_host`（`ssh -G dest` 解析 `hostname` 行，dest 级 HashMap 缓存，失败退原样）+ 可测的 `parse_ssh_g_hostname`。
- **input_bar.rs**：
  - `history: Vec<Entry>` 吃掉平行数组 `history_cwds`；新增 `frequent` / `browse`（↑ 走序物化）/ `focus_host`；
  - `set_history_entries(entries, frequent)`；`set_focus_cwd` → `set_focus_scope(host, cwd)`；`set_last_history_cwd` → `set_last_history_scope(host, cwd)`（含同作用域孪生折尾 = 会话内全局去重）；
  - `rebuild_browse` 严格两态：作用域有历史走作用域（ts 降序）→ 否则频次池 → 无焦点快照时全历史（ts 降序）；
  - `history_previous/next` 改按 browse 走（pos 0 = 第一脚 ↑ 的条目，尾端钳制）；ghost 扫描同源 browse（作用域外历史不再泄漏进 ghost）；
  - MAX_HISTORY(255) 删除，内存上限即 MAX_ENTRIES(1万)。
- **screen/mod.rs**：`history_scope` / `history_scope_with`（本地 `''` + OSC7→探测；ssh 走归一化 host + 仅信 OSC7，远端无 integration 退化 `(host, '')`）；Tab 与提交共用；提交 stamp/focus/record 重排（stamp 不再被 record_history=false 关闭）；启动加载换 `load()`。

## 待用户手测

1. 本地：在目录 A 跑几条命令 → cd 目录 B → ↑ 只见 B 的命令；回 A ↑ 第一脚是 A 最近一条；全新目录 ↑ 出全局最常用命令。
2. 重跑同一命令后 ↑ 该命令沉到第一位（同作用域去重移尾）。
3. 重启回显：库中历史原样回来（含 exit 列的 OSC 133 回填仍准）。
4. ssh：进会话后 cd 各远程目录，↑ 按远程目录隔离；无 shell integration 的远端整台机器聚一个作用域；alias 与 IP 连同一机器时历史合流（ssh -G 归一化）。
5. 密文行不入库（回归）；多窗口同时提交互不丢（WAL）。
