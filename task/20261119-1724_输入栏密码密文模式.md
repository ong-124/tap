# 任务：输入栏密码密文模式

## 背景与目标

修复轮次八（20261118-1941 任务）把锁定判定收敛为 ALT_SCREEN 后，sudo / ssh 口令等非全屏交互输入统一进入输入栏缓冲，密码明文回显在输入栏内，且提交后会写入本地持久历史库（`{config_dir}/input-history`）。目标：输入口令时自动切换密文模式（字符画 `•`），并且不落历史。

## 方案（20261119-1724 获批「仅自动检测」，检测规则经修复轮次一精化）

**检测信号 = PTY 线路规程「`ECHO` 关 + `ICANON` 开」**：sudo/ssh/`read -s`/`getpass` 读口令时只关回显、保留 canonical 行规程（退格/Ctrl+U 仍由内核处理）。zsh ZLE、bash readline 这类行编辑器虽然也关回显（自己回显），但同时是 raw 模式（`ICANON` 也关）——`ICANON` 是区分二者的关键（首轮仅判 `ECHO` 导致正常提示符全部误掩码，见修复轮次一）。Linux/macOS 下对 PTY master fd 调 `tcgetattr` 读到的即从站线路规程设置（master/slave 共享 termios）。探测点在击键/粘贴进入输入栏缓冲之前，微秒级 syscall，无需后台轮询线程与事件通道。

### 行为设计

- **密文模式**：每字符画 `•`（字符数不变，横向滚动/caret 数学照搬）；压制虚化预选（refresh_suggestion 判 `!masked`）与 Tab 补全（tab_complete 早退）；IME preedit 仍可见（未提交的组合内容）
- **sticky**：一旦置位不因回显恢复而解除，仅随行生命周期复位（提交 take_submitted_line / Ctrl+C 与清空 clear / 载入历史条目 load_at / set_history）——保证密码不二次明文显形
- **历史跳过**：内存历史（take_submitted_line 内跳过 push）与持久历史库（submit 侧显式 `!was_masked`，防「密码恰好等于末条历史」被相邻去重放过）双重拦截
- **历史浏览语义**：↑ 载入历史条目 = 公开内容，解除密文；↓ 回到 draft 时按 `draft_masked` 恢复原密文态（draft 存的可能是密码）

## 已知边界

- 检测不到的场景无信号可依：`read -p`（回显开着）、采用 raw 模式读口令的非主流实现——仍明文进缓冲（现状已如此）
- ssh 会话内：本地 pty 整个会话都是 raw（`ICANON` 关，ssh 自己搬运字节），远程 sudo/口令提示无法从本地 termios 识别——不掩码
- 密文行跨 pane 粘性共享（输入栏缓冲全局单份）：口令输入中途切 pane 继续输入，新内容一并掩码、不落历史——安全优先的取舍
- Windows（ConPTY 无 termios）：探测恒为非口令，不掩码

## 修复轮次一（20261119-1741，正常提示符误掩码）

**用户反馈**：正常模式（非密码）输入的命令全部变成 `•`。根因：检测只看 `ECHO`——zsh ZLE / bash readline 行编辑器在提示符处就是「回显关」状态（raw 模式，自己管理整行回显），正常打字被误判为口令输入。

**修复**：探测函数改 `secret_prompt_expected(fd)` = `ECHO` 关 **且** `ICANON` 开（口令提示保留 canonical，行编辑器是 raw）——`ICANON` 是二者的区分位。探测失败/非口令一律不掩码。单测补齐三种从站规程（默认、raw 行编辑器、canonical 口令）与失败路径。

验证：teletypewriter 17 / tapterm 336 测试通过、clippy/fmt 干净。待用户手测：正常提示符输入不再变 `•`；sudo/ssh 本机口令仍显 `•` 且不落历史。
