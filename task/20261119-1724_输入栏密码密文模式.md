# 任务：输入栏密码密文模式

## 背景与目标

修复轮次八（20261118-1941 任务）把锁定判定收敛为 ALT_SCREEN 后，sudo / ssh 口令等非全屏交互输入统一进入输入栏缓冲，密码明文回显在输入栏内，且提交后会写入本地持久历史库（`{config_dir}/input-history`）。目标：输入口令时自动切换密文模式（字符画 `•`），并且不落历史。

## 方案（20261119-1724 获批「仅自动检测」）

**检测信号 = PTY 回显状态（termios `ECHO`）**：sudo/ssh 口令提示读取输入前都会关闭终端回显，这是程序级行为、与提示词语言无关。Linux/macOS 下对 PTY master fd 调 `tcgetattr` 读到的即从站线路规程设置（master/slave 共享 termios，WezTerm 密码掩码同方案）。探测点在击键/粘贴进入输入栏缓冲之前，微秒级 syscall，无需后台轮询线程与事件通道。

### 行为设计

- **密文模式**：每字符画 `•`（字符数不变，横向滚动/caret 数学照搬）；压制虚化预选（refresh_suggestion 判 `!masked`）与 Tab 补全（tab_complete 早退）；IME preedit 仍可见（未提交的组合内容）
- **sticky**：一旦置位不因回显恢复而解除，仅随行生命周期复位（提交 take_submitted_line / Ctrl+C 与清空 clear / 载入历史条目 load_at / set_history）——保证密码不二次明文显形
- **历史跳过**：内存历史（take_submitted_line 内跳过 push）与持久历史库（submit 侧显式 `!was_masked`，防「密码恰好等于末条历史」被相邻去重放过）双重拦截
- **历史浏览语义**：↑ 载入历史条目 = 公开内容，解除密文；↓ 回到 draft 时按 `draft_masked` 恢复原密文态（draft 存的可能是密码）

## 已知边界

- 检测不到的场景无信号可依：`read -p`（回显开着）、非 PTY 图形密码框——仍明文进缓冲（现状已如此）
- 密文行跨 pane 粘性共享（输入栏缓冲全局单份）：口令输入中途切 pane 继续输入，新内容一并掩码、不落历史——安全优先的取舍
- Windows（ConPTY 无 termios）：探测恒为回显开启，不掩码
