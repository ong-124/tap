# 任务：配置文件默认位置改为 tap 目录

## 背景与目标

项目为 rio fork（tap），配置默认目录仍沿用 `rio` 命名。目标：默认配置位置改为 `~/.config/tap/config.toml`（Linux/macOS），Windows 为 `%LOCALAPPDATA%\tap\config.toml`，与 fork 名称一致。

## 设计

- 配置目录唯一入口：`rio-backend/src/config/mod.rs::config_dir_path()`（三平台各一个变体，均 `.join("rio")`）
- `config_file_path()`、themes 目录、log 目录（rioterm main）、welcome 路由、配置文件 watcher 均经由 `config_dir_path()` 派生，改一处即全部生效
- `RIO_CONFIG_HOME` 环境变量覆盖机制保留，不受影响

## 关键子任务

1. 三平台 `config_dir_path()` 默认目录 `rio` → `tap`
2. 编译验证
3. 迁移说明（旧 `~/.config/rio/config.toml` 需手动移动/复制到新位置）

## 实施记录

- `rio-backend/src/config/mod.rs::config_dir_path()` 三个平台变体的默认目录 `rio` → `tap`：
  - Linux：`$XDG_CONFIG_HOME/tap`（默认 `~/.config/tap`）→ `~/.config/tap/config.toml`
  - macOS：`~/.config/tap`
  - Windows：`%LOCALAPPDATA%\tap`
- 派生路径全部自动跟随：`config_file_path()`、themes 目录、log 目录（rioterm main）、welcome 路由、配置 watcher
- `RIO_CONFIG_HOME` 环境变量覆盖机制保留不变
- 范围外未动：shell integration 脚本目录（`~/.cache/rio/...`，属缓存目录）、TERM_PROGRAM、通知 icon 等品牌字符串
- 编译验证：`cargo check -p rioterm` 通过（`-p rio-backend` 默认 feature 本平台缺 wayland/x11 不可编译，为存量现象）
- 迁移提示：已有配置需从 `~/.config/rio/config.toml` 移动/复制到 `~/.config/tap/config.toml`（或设 `RIO_CONFIG_HOME` 指向旧目录）
