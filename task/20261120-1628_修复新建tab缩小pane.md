# 修复新建 tab 使 pane 逐个缩小一个输入栏高度

## 背景

用户报告：每创建一个新 tab，pane 内容区就缩小一个输入栏的高度；tab 越多缩得越多（复利式缩减）。

## 根因

`ContextManager::add_context`（frontends/tapterm/src/context/mod.rs）在为新 tab 构建 dimension 时：

- 单分屏分支克隆当前 pane 的 `current.dimension`。而 `apply_taffy_layout`（layout/mod.rs）会把每个 pane 的 `dimension.width/height` 覆写为 taffy 布局后的 panel `layout_rect` 尺寸——窗口边距（含输入栏高度的 `scaled_margin.bottom`）已被 root 扣除。
- 该 dimension 传入 `ContextGrid::new` 后被当作窗口尺寸再次扣减 `scaled_margin` → 双重扣减。
- 新 tab 的 pane 布局因此缩一圈；下一个 tab 又克隆这个已缩小的 pane dimension → 每建一个 tab 多扣一份，逐 tab 复利。

多分屏分支走的 `grid_dimension()` 是正确实现：用 grid 级 `width/height`（窗口尺寸）加反缩放 margin 重建，不会重复扣减。

## 设计

`add_context` 无条件改用 `self.current_grid().grid_dimension()`，删除单分屏分支的 pane dimension 克隆。`grid_dimension()` 内部自取 scale/cell/行高/字号并反缩放 margin，语义即为「新 tab 继承窗口级可用区域」。

## 实施记录

- frontends/tapterm/src/context/mod.rs：`add_context` 中 `let mut dimension = current.dimension;` + `if len() > 1` 条件改为无条件 `grid_dimension()`，注释说明 pane dimension 是 post-margin panel rect 不能复用。
