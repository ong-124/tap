# 清理 build 刷屏警告

## 背景

`cargo build` 每次全量/增量编译输出约 20 条警告刷屏，掩盖有效输出。逐条核查后按「真实问题修复」与「cfg/测试门控误报标注」两类处理，不动运行时行为。

## 警告分类与处理

### 真实问题（直接修复）

- 未用 import ×3：`rio-backend/src/config/navigation.rs`（`deserialize_to_arr_opt`）、`frontends/rioterm/src/context/mod.rs` 与 `layout/mod.rs`（`Rect`）。
- 未用变量：`teletypewriter/src/unix/mod.rs` 的 `uses_default_shell` 仅在 macOS cfg 块使用，绑定加 `#[cfg(target_os = "macos")]` 门控（非简单下划线改名，保留 macOS 语义）。
- 函数指针整数直转：`rio-window/.../x11/ime/context.rs` 的 `preedit_start_callback as usize` → `as *const () as usize`。
- 冗余 `homepage`：`corcovado/Cargo.toml` 与 `repository` 同值，删除。
- 孤儿源文件：`frontends/rioterm/src/renderer/font_cache.rs` 无任何 `mod` 声明、从未参与编译（上游遗留），删除；连带 rioterm 的 `lru` 依赖一并移除，`futures` 同为未用依赖。

### cfg/测试门控导致的误报（保留代码，标注或调整清单）

- `rioterm` 死代码三条：`BorderConfig.color`（分屏分隔线配色已从配置接入、渲染尚未接上）、`should_draw_borders`（compute_tests 断言使用）、`InputBar::set_metrics`（输入栏测试使用）——`cargo build` 不编译测试故报 dead_code。按项目已有 `#[allow(dead_code)]` 惯例标注并注明用途。
- `rio-backend` 的 `onig` 仅 hints 单测使用 → 移入 `[target.'cfg(not(target_arch = "wasm32"))'.dev-dependencies]`；`url` 全源码无引用 → 删除。
- `rioterm` 的 `wgpu` 仅在 build.rs 定义的 `cfg(wgpu_backend)` 下引用（Linux 默认关闭）→ 改 `optional = true` 并在 `wgpu` feature 中加 `dep:wgpu`，与 sugarloaf 的模式一致。
- `sugarloaf` 的 `futures`（仅 webgpu.rs）、`rayon` / `thiserror`（仅 wgpu-gated librashader 滤镜链）→ 改 optional 并挂入 `wgpu` feature（`dep:` 语法）；确认全无引用的 `approx` / `lru` / `guillotiere` / `halfbrown` / `fontconfig-parser` → 删除。
- `librio-wasm` 整 crate 被 `#![cfg(target_arch = "wasm32")]` 门控，native 构建下依赖全报未用 → `[dependencies]` 改为 `[target.'cfg(target_arch = "wasm32")'.dependencies]`。
- 根 workspace 6 个依赖（`wasm-bindgen` / `wasm-bindgen-futures` / `wasm-bindgen-test` / `env_logger` / `console_log` / `console_error_panic_hook`）无任何成员经 `workspace = true` 引用 → 删除；`frontends/wasm` 不在 workspace members 中（不可经根 workspace 构建），其引用的 4 个版本就地内联保持清单自洽。
