# 鼠标点击不改 pane 焦点

## 状态变更记录

- [20261120-1606] 待开始 → 已完成：实现完成，tap-backend 229 / tapterm 376（+1）测试通过，待用户手测

## 背景

`disable-mouse = true`（默认）下鼠标保留了文本选中 essentials（任务 20261119-1310 修复轮次一），但为让拖拽选中落在指针所在 pane，按下时会把点击的 pane 切为焦点（click-to-focus）。用户要求：鼠标可用，但点击不得改变 pane 焦点——键盘焦点、输入栏路由、焦点环、CSI 焦点报告都应留在原 pane。

## 设计：选择目标 latch（press–drag–release 周期锁定）

核心思路：把「点击即焦点切换」改为「按下时把指针所在 pane 锁定为本次鼠标选择周期的目标」，选择类操作寻址目标 pane，键盘焦点（grid `current`）全程不动：

- **`ContextGrid` 新增 `mouse_pane: Option<NodeId>`**（layout/mod.rs）：
  - `mouse_selection_target_begin(&mouse)`：多 pane 且指针落在非焦点 pane 时 latch，返回是否 latch；单 pane / 点在焦点 pane / 点在间隙均不 latch
  - `mouse_selection_target_end()`：释放 latch
  - 访问器 `mouse_target` / `mouse_target_mut` / `mouse_target_with_computed_dimension`：latch 未生效时回落 `current`，几何变体带目标 pane 绝对偏移（窗口坐标→pane 网格坐标）；latch 悬空（拖拽中 pane 被关）回落焦点 pane
- **`ContextManager` 转发** `mouse_target()` / `mouse_target_mut()`
- **`Screen` 鼠标路径 helper 全部改寻址目标 pane**（latch 未生效时行为与旧 `current()` 完全一致，非 disable-mouse 路径零变化）：`mouse_position`、`side_by_pos`、`selection_scroll_delta`、`selection_scroll_tick`、`copy_selection`、`clear_selection`、`start_selection`、`update_selection`、`selection_is_empty`、`on_left_click` 的 vi 光标移动；新增 `mouse_selection_display_offset()`（目标 pane 的滚动偏移）
- **application.rs `disable-mouse` 按下路径**：删 `select_current_based_on_mouse()`（click-to-focus）改 `begin_mouse_selection_cycle()`，点击落点 pane 的 `on_left_click` 照常执行（其 Click 分支先清目标 pane 残留选区再起新选区，旧注释「焦点切换点击不达 on_left_click」的前提随之消失）；中键粘贴（`process_mouse_bindings` → `paste`）仍进键盘焦点 pane
- **latch 生命周期**：松开（左/右键 release 复制 PRIMARY 之后）与窗口失焦（release 永不到达）时 `end_mouse_selection_cycle()`
- **`disable-mouse = false`（完整鼠标路径）不动**：该路径的 click-to-focus 同时服务 vim 等鼠标上报的路由（`mouse_report` 发往焦点 pane），删除会破坏分屏下的鼠标捕获程序

## 明确不做

- 不加配置项（行为即新默认，无回退开关）
- 不动完整鼠标路径（`disable-mouse = false`）的 click-to-focus
- 不顺手修两处既有遗留（净树上同样存在）：tap-vt `test_single_capability_requests` 失败（rio→tap 改名后测试期望未跟上）、clippy 1.100 新 lint `manual_slice_fill`（input_bar.rs 密文循环）、18 个非本次触碰文件的 rustfmt import 乱序（改名把 `rio_backend`→`tap_backend` 破坏了字母序）
